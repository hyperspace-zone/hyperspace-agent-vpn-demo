# Voiceover Script: Hyperspace IP-to-IP VPN Demo

## Короткая версия

### 1. Landing

Перед нами Hyperspace. Это сетевой слой для низколатентного доступа к
интернету через клиентский VPN. Идея простая: приложениям и агентам все чаще
нужен не просто доступ в сеть, а предсказуемый маршрут, стабильная задержка и
понятная модель оплаты за конкретную сетевую задачу.

В этом демо я показываю один конкретный сценарий: агент покупает короткую
IP-to-IP VPN-сессию, подключает ее на сервере и сразу проверяет, как меняется
качество сетевого пути.

### 2. Problem

Обычный VPN обычно предполагает аккаунт, подписку, ручную настройку и
долгоживущую конфигурацию. Для автономного агента это неудобно. Агенту нужен
другой интерфейс: увидеть цену, оплатить доступ, получить конфиг, выполнить
задачу и закрыть сессию.

Здесь Hyperspace работает как программируемый сетевой ресурс. Агент обращается
к API, получает HTTP 402 payment challenge, оплачивает минимальную сумму в
USDC через Solana mainnet и получает WireGuard config, ограниченный конкретным
направлением: от IP этого сервера до target IP.

### 3. Setup

Я запускаю инструкцию на чистом Ubuntu 24.04 сервере. В основной версии README
Solana CLI не нужен: адрес кошелька и балансы проверяются локальным Node.js
скриптом, который читает `id.json` и запрашивает Solana JSON-RPC.

Сначала ставятся базовые пакеты, WireGuard tools, Node.js 22 из NodeSource.
Затем я клонирую репозиторий, подкладываю заранее пополненный `id.json` вне
репозитория и проверяю кошелек командой `npm run wallet-info`.

В выводе видно адрес, ссылку на Solscan, баланс SOL для комиссий и баланс USDC
для оплаты доступа.

### 4. Configure

Дальше я ставлю локальный pay CLI через `npm install @solana/pay`. Глобальная
установка не нужна: бинарник лежит в `./node_modules/.bin/pay`, а `.env`
ссылается именно на него.

После этого я задаю два IP:

`HYPERSPACE_SOURCE_IP` - стабильный egress IP этого сервера.

`HYPERSPACE_TARGET_IP` - IP назначения, для которого будет выпущен платный
VPN-конфиг.

В этом прогоне target - `185.97.160.8:443`. Это же направление используется для
TCP jitter measurement.

### 5. Payment Challenge

Команда `npm run challenge` показывает сырой HTTP 402 / MPP challenge. Сервер
не выдает конфиг бесплатно. Он возвращает payment headers, где указаны сеть,
цена и payment request.

Важно, что challenge говорит `network: mainnet` и цена равна `0.000001 USDC`.
Перед оплатой скрипт `buy-vpn` дополнительно проверяет, что цена не выше
разрешенного лимита `PAY_YOLO_UPTO`.

### 6. Baseline

Перед покупкой я запускаю baseline measurement. Это 30 TCP connect попыток до
target IP напрямую, без Hyperspace VPN.

В последнем прогоне direct path дал примерно:

`median: 29.834 ms`

`p95: 98.935 ms`

`stddev jitter: 33.136 ms`

То есть медиана неплохая, но хвост задержки и jitter очень заметные.

### 7. Buy And Connect

Теперь агент покупает VPN-доступ командой `npm run buy-vpn`. После оплаты API
возвращает WireGuard config.

Важная деталь: это IP-to-IP VPN config. В нем `AllowedIPs` уже равен
`185.97.160.8/32`, то есть туннель применяется только к нужному target IP.
Скрипт ничего не переписывает и подключает ровно тот конфиг, который выдал
сервер:

`sudo bash scripts/04-connect-wireguard.sh`

WireGuard поднимает интерфейс `hyperspace-demo`, добавляет маршрут только до
target IP и показывает активного peer.

### 8. VPN Measurement

Теперь я повторяю те же 30 TCP connect измерений, но уже через Hyperspace VPN.

В последнем no-Solana-CLI прогоне результат был:

`median: 32.930 ms`

`p95: 33.559 ms`

`stddev jitter: 0.342 ms`

Медиана стала примерно на 3 ms выше, но хвосты и jitter резко улучшились. Для
real-time сценариев это часто важнее, чем минимальная медианная задержка:
маршрут становится предсказуемым.

### 9. Compare

Команда `npm run compare` сводит direct и VPN measurements в одну таблицу.

В этом прогоне p95 улучшился примерно на 65 ms, а jitter снизился примерно с
33 ms до 0.3 ms. Это и есть смысл демо: агент не просто купил VPN-конфиг, он
получил измеримое улучшение качества сетевого пути для конкретной задачи.

### 10. Cleanup

В конце я отключаю WireGuard и отзываю сессию:

`sudo bash scripts/07-disconnect-wireguard.sh`

`npm run revoke`

Сессия prepaid и короткоживущая. Агент купил доступ, использовал его, сохранил
timestamped отчеты и закрыл ресурс.

## One-Minute Cut

Hyperspace - это низколатентный сетевой слой через клиентский VPN. В этом демо
я показываю, как автономный агент может купить не подписку и не ручной VPN, а
короткую IP-to-IP VPN-сессию для конкретного маршрута.

На чистом Ubuntu сервере я ставлю Node.js и WireGuard tools, клонирую демо,
подкладываю заранее пополненный Solana `id.json` и проверяю баланс через
Node.js скрипт без Solana CLI.

Дальше агент получает HTTP 402 / MPP challenge, видит цену `0.000001 USDC`,
покупает доступ и получает WireGuard config, ограниченный target IP:
`185.97.160.8/32`.

До VPN direct path показывает хорошую медиану, но плохие хвосты:
`p95` около 99 ms и jitter около 33 ms. После подключения через Hyperspace
медиана становится около 33 ms, зато `p95` падает до 33.5 ms, а jitter - до
0.3 ms.

В конце агент отключает WireGuard и отзывает сессию. Это показывает модель
программируемой сети для AI agents: discover, pay, connect, measure, revoke.
